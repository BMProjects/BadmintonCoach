# 实验框架：具名线热图 + 求交（多骨干对比）

目标：在**视角变换数据集**上，初步训练/对比几种骨干网络（配各自的 neck/head），找出
"线热图 + 求交"路线下**最有潜力的网络框架**，指导后续改进。2D→3D 标定为**离线终点**，
初期不强调轻量化。

## 0. 核心设计决策

- **具名线**而非无名线：网络直接输出每条球场线的身份（通道即身份），**几何阶段退化为
  已知对应点的 DLT/最小二乘**，不再在低角度畸变白线上做 RANSAC（已证实不可行）。
- **对称性交给网络 + 数据 + 朝向判别**，不交给几何：视角增广让网络学透视线索区分近/远、
  左/右；辅助输出一个"近端朝向"标量做 tiebreak。
- 离线优先：先比"线/角点/单应性质量"，速度只作次要参考。

## 1. 任务与监督目标（所有模型共用）

输入：单帧 RGB（短边 ~512–768）。输出多任务热图：
- **具名线热图** `L` 通道：每条 BWF 球场线一张细线高斯热图（线身份=通道）。
  - 线集合（建议 ~10–13 条）：两底线、两双打边线、两单打边线、两短发球线、
    两双打长发球线、中线两段。
- **辅助角点热图** `K` 通道（可选）：线交点（复用现有 22 点标注），监督更稳、也可直接评估。
- **朝向标量**（可选）：近端方向（破 180° 对称）。

标签生成：**复用现有交叉点/角点标注**，按 BWF 连接关系**渲染具名线**（点→线，零额外标注）。
线热图 = 线段栅格化后高斯模糊；角点热图 = 点高斯。

## 2. 数据管线（视角变换数据集）

- 源：`data/court_kp_official`（22 点）+ 30-kp 家族 + 业余标注（4 角→22 点）。
- **视角增广**（核心）：随机单应性 warp（已实现 `dataset._perspective`）模拟低角度/斜视；
  叠加色彩/光照/遮挡(贴随机块模拟球员)。
- **按视角留出测试**：训练集与测试集**用不同的 warp 视角/不同场馆**，专测"换视角"泛化；
  额外保留一个**真实低角度子集**（业余图）单独评测。
- 产出：image + line-heatmaps + kp-heatmaps + 可见性/朝向。

## 3. 模型工厂：骨干 × neck × head（可插拔）

统一接口 `build_model(backbone, neck, head, n_lines, n_kpts)`，逐项对比。

| 骨干（新/强） | 特点 | 适配 neck | 适配 head |
|---|---|---|---|
| **HRNet-W32 / Lite-HRNet** | 全程多分辨率，热图精度强 | **原生多分辨率**（无需 FPN，轻融合即可）| 线热图 + 角点热图 |
| **ConvNeXt-V2(-T)** | 现代强 CNN | **U-Net/FPN** 融合 /4../32 | 同上 |
| **EfficientViT-L / FastViT / RepViT** | 高效 conv-transformer | **FPN/简化 BiFPN** | 同上 |
| **(可选) LETR / Deep-Hough 头** | 直接出线参数 | — | 线参数回归（另一范式对照）|

设计原则：
- **/32 类骨干必须配高分辨率融合 neck**（U-Net skip 或 FPN），细线定位的关键。
- **HRNet 系列自带高分辨率**，neck 极简。
- head 统一输出 /4 或 /2 分辨率热图，便于公平对比；可加 1–2 层 refine。

## 4. 解码与（离线）标定

1. 每条线热图 → 阈值/骨架化 → **拟合直线**（加权最小二乘 / RANSAC-on-inliers，仅在单条线
   内部，规模小、稳定）。
2. 具名线**两两求交** → 带身份的角点（可外推到画面外，解决边缘角点）。
3. 角点世界坐标已知（`court_kp_official_world.json`）→ **直接 DLT 单应性**（+PnP 出相机）。
4. 朝向 tiebreak 修正近/远。

## 5. 评测指标与对比协议

按潜力排序看，主指标在**换视角测试集 + 低角度子集**上：
- **线质量**：预测线与 GT 线的 Chamfer/角度+截距误差；线命中率。
- **角点 PCK@{0.01,0.02,0.05}**（由求交得到 vs GT 交点）。
- **单应性/全场重叠** `court_overlap_score`（最终标定质量，最重要）。
- **低角度成功率**：低角度子集上 overlap>阈值 的比例（这条最能区分"潜力"）。
- 次要：params / FLOPs / latency。

每个 (backbone,neck,head) 配置 → 一行结果，汇总成表，看谁在**换视角/低角度**上最强。

## 6. 框架落地（建议目录）

```
training/court_lines/
  dataset.py     # 线+角点热图标签生成 + 视角增广 + 留出视角划分
  models/
    factory.py   # build_model(backbone,neck,head)
    backbones.py # hrnet/litehrnet/convnextv2/repvit/fastvit (timm)
    necks.py     # unet_fpn / bifpn / identity(hrnet)
    heads.py     # line_heatmap_head (+aux kp head)
  decode.py      # 线拟合→求交→DLT 单应性 (+朝向 tiebreak)
  metrics.py     # chamfer/PCK/overlap/低角度成功率
  train.py       # 共用训练循环(AMP/RAM缓存/多worker, 复用 court_kp)
  run_experiments.py  # 扫配置矩阵 -> results 表
configs/experiments/*.yaml   # 每个 backbone×neck×head 一个
```

## 7. 分阶段计划

- **P1**：线标签生成 + 视角增广 + 评测指标 + 一个基线(ConvNeXt-V2 + U-Net + 线热图)跑通。
- **P2**：加 HRNet / EfficientViT / RepViT，统一 head，扫表对比换视角/低角度。
- **P3**：选最优框架，加朝向 tiebreak + 单条线 RANSAC 精修，接离线 2D→3D。
- **P4**：把胜出模型接回 court_calibrator（新后端 `line_heatmap`），与 heatmap/line_fit 并存（auto 择优）。

> 复用：现有 `training/court_kp`（AMP、RAM 缓存、多 worker、负样本、court_overlap_score、
> 视角增广 `_perspective`、`court_kp_official_world.json`）大部分可直接搬到 `court_lines`。

## P1 实测结果（2026-06-14）

**设置**：`data/court_kp_official`（train 918 / valid 202），输入 384、线热图 96（/4），
12 具名线通道，σ=2.5；**训练与验证集均开启透视+仿射换视角增广**（perspective jitter 0.13，
旋转 ±7°，缩放 0.85–1.15，平移 ±6%）。骨干 ImageNet 预训练 + FusionNeck（各尺度 1×1→128ch
上采样到 /4 求和 + 两层 3×3）+ 1×1 线热图头。Adam lr 1e-3 cosine，bf16 AMP，30 epoch。
评测：逐通道阈值取脊线 → `cv2.fitLine` → 按 `KPT_TO_HV` 求 H∩V 交点还原 22 个关键点，
对可见 GT 算 PCK（按输入对角线归一）/ 中位像素误差 / 覆盖率。

| backbone | params(M) | PCK@0.05 | PCK@0.02 | med_px | mean_px | cov | min |
|---|---|---|---|---|---|---|---|
| convnextv2_nano | 15.4 | **0.991** | **0.979** | 2.94 | 4.40 | 1.00 | 3.1 |
| efficientvit_b1 | 5.0 | 0.984 | 0.978 | **2.92** | 4.86 | 1.00 | **2.6** |
| repvit_m1 | 5.1 | 0.979 | 0.963 | 2.95 | 7.74 | 1.00 | 2.6 |
| hrnet_w18 | 11.5 | 0.983 | 0.970 | 2.92 | 5.50 | 1.00 | 4.1 |

**参照基准**：用 GT 热图直接走同一解码链路，中位误差 ≈ 2.4px——即解码在 /4 分辨率下的栅格化下限。

### 结论

1. **方案本身成立**：四个骨干在换视角验证集上 **coverage 全部 = 1.00**，即每张图 22 个关键点
   都能由具名线求交还原（含画面外角点靠直线外推）。中位误差 ~2.9px 已逼近解码下限 2.4px，
   说明网络预测的线几乎和 GT 一样准。低角度透视形变下不需要 RANSAC 做身份搜索——具名通道
   把"哪条线"直接编码进了输出，这正是相对点热图方案的核心优势。

2. **任务已饱和，骨干差异极小**：PCK@0.05 在 0.979–0.991 之间，中位误差几乎相同。瓶颈是
   /4 解码栅格化下限，不是骨干容量。因此选型应由**效率**决定，而非精度。

3. **最有潜力的框架：`efficientvit_b1`**。以 5.0M 参数（convnextv2 的 1/3）、最快训练
   （2.6 min）拿到几乎相同的 PCK@0.05 0.984 / PCK@0.02 0.978，且 mean_px 比 repvit 稳得多。
   repvit_m1 同量级但 mean_px=7.74 偏高（个别线拟合崩坏，尾部误差大），稳健性次之；
   hrnet_w18 多尺度并未带来精度增益，反而最慢；convnextv2_nano 精度名义最高但 3× 参数不划算。

### 下一步（P2/P3）

- 提解码下限：线热图升到 /2（192）或加 soft-argmax/亚像素脊线拟合，把 2.4px 下限压到 ~1px。
- 加难样本：更大透视抖动 + 真实低角度业余素材，拉开骨干差距再复评。
- 朝向 tiebreak（中心对称 180° 消歧）+ 单条线 RANSAC 精修，接离线 2D→3D 标定。
- 以 efficientvit_b1 为基线接回 `court_calibrator` 新后端 `line_heatmap`。

## P2 实测结果（2026-06-14）：压解码下限 + 加难样本

P1 发现精度被 /4 解码栅格化下限卡住（~2.9px），骨干差异被掩盖。P2 三个改动：

1. **输出升到 /2**（热图 192，`out_div=2`，neck 融合到 input/2）——降栅格化下限。
2. **加权亚像素解码**（`fit_line_weighted`，强度加权 TLS 拟脊线）——降尾部误差。
3. **hard 增广**（透视抖动 0.13→0.22，旋转 ±12°，缩放 0.7–1.3）——模拟更极端低角度视角。

### 解码下限探针（用 GT 热图直接解码，120 张换视角图）

| 输出分辨率 | 解码 | std aug med/mean | hard aug med/mean |
|---|---|---|---|
| /4 | hard fit | 3.11 / 3.34 | 3.20 / 3.44 |
| /4 | weighted | 3.14 / 3.31 | 3.20 / 3.83 |
| **/2** | hard fit | 1.62 / 1.70 | 1.62 / 1.93 |
| **/2** | **weighted** | **1.58 / 1.58** | **1.61 / 1.80** |

**结论**：下限由**输出分辨率**主导（线在热图栅格上栅格化，量化 ±0.5 格即下限），/4→/2 直接腰斩
（3.1→1.6px）；加权解码在 /4 几乎无效（GT 线本身已量化到 /4 整数端点），但在 /2 上能压低 mean/尾部。

### 训练结果（/2 + 加权解码 + hard 增广，30 epoch）

| backbone | params(M) | PCK@0.05 | PCK@0.02 | med_px | mean_px | min |
|---|---|---|---|---|---|---|
| convnextv2_nano | 15.4 | 0.941 | 0.921 | 1.67 | 17.7 | 3.2 |
| efficientvit_b1 | 5.0 | 0.943 | 0.931 | 1.57 | **13.7** | **3.0** |
| repvit_m1 | 5.1 | 0.955 | 0.941 | 1.58 | 25.7 | 3.0 |
| hrnet_w18 | 11.5 | **0.959** | **0.949** | **1.51** | 13.8 | 5.2 |

（对比 P1 /4 标准增广：med ~2.9px、PCK@0.05 ~0.98。）

### 分析与结论

1. **下限目标达成**：训练模型中位误差从 P1 的 ~2.9px 降到 **~1.5px**，/2 输出的收益完整传导到模型。
   hard 增广把 PCK@0.05 从 ~0.98 拉到 0.94–0.96，骨干差异开始显现——增广确实在区分能力。

2. **新发现：重尾**。median ~1.5px 但 **mean 高达 13–26px**——极端视角下**稀疏线**（如只有 2 个可见点的
   双打后发球线）拟合不稳，两条略偏的线求远处画面外角点交点时误差放大。这是 P2 暴露的真正瓶颈，
   **不是骨干容量，而是线选择/求交的稳健性**，正是 P3（朝向消歧 + 单线 RANSAC 精修 + 稳健求交）要解决的。

3. **骨干结论（更新）**：hard 下 `hrnet_w18` 精度名义最高（PCK@0.05 0.959）但 11.5M + 最慢；
   **`efficientvit_b1` 仍是最优性价比**——5.0M、最快、med 1.57px，且 **mean 13.7px 为全场最低**
   （稳健性最好）；`repvit_m1` PCK 不错但 mean 25.7px（重尾最严重，个别线崩坏），稳健性最差，
   不推荐做基线。**维持以 efficientvit_b1 作为后续基线**。

### 下一步（P3）

- 治重尾：每通道脊线先 RANSAC 去离群点再加权拟合；稀疏线（≤2 点）用 BWF 球场模型先验约束。
- 中心对称 180° 朝向 tiebreak（用近/远端非对称特征，如发球线间距）。
- 进一步降下限可在渲染端用 `cv2.LINE_AA`+亚像素 `shift` 画线消除端点量化（当前用整数端点）。
- 以 efficientvit_b1 接离线 2D→3D 标定，回灌 `court_calibrator` 新后端 `line_heatmap`。

## P3 实测结果（2026-06-14）：治重尾 + 降下限 + 朝向可学性

P2 暴露的瓶颈是**重尾**（median ~1.5px 但 mean 13–26px）：极端视角下稀疏/双模脊像素把加权拟合带偏，
远处画面外交点放大。P3 三个改动（与 P2 同为 /2 + hard 增广，故为干净消融）：

1. **AA 亚像素渲染**（`cv2.LINE_AA` + 1/16px `shift` 画线）——消除 GT 线端点的整数量化，进一步降下限。
2. **稳健解码 `fit_line_robust`**（加权拟合 + MAD 离群剔除再拟合）——剔除少数派第二模态而**不损失脊线主体**
   （RANSAC 实测在干净脊上反而更差：thr 太紧把有宽度的脊剔成片段，GT 下限从 0.82px 劣化到 2.26px）。
3. **180° 翻转增广**（`flip180`，图像旋转 180° + 关键点按对称置换 `SYM_PERM=21-i` 重标）——
   测具名通道模型能否仅凭画面内容（透视前缩）分辨观察端（近/远），即对称消歧是否非要显式几何 tiebreak。

### 解码下限探针（GT 热图直解，/2，hard 增广，120 张）

| 渲染 | 解码 | med / mean (px) |
|---|---|---|
| 普通 | weighted | 1.60 / 1.76 |
| 普通 | ransac | 2.67 / 3.21（劣化，弃用） |
| **AA** | weighted | 0.82 / 1.14 |
| **AA** | **robust** | **0.81 / 1.06** |

### 训练结果（/2 + AA + robust + hard，30 epoch）

| backbone | params(M) | PCK@0.05 | PCK@0.02 | med_px | mean_px | min |
|---|---|---|---|---|---|---|
| convnextv2_nano | 15.4 | 0.955 | 0.941 | 0.85 | 11.9 | 3.2 |
| **efficientvit_b1** | **5.0** | **0.968** | **0.959** | 0.61 | **6.33** | **3.1** |
| repvit_m1 | 5.1 | 0.954 | 0.942 | 0.61 | 13.3 | 3.0 |
| hrnet_w18 | 11.5 | 0.960 | 0.950 | **0.43** | 7.53 | 5.2 |

### efficientvit_b1 三阶段进展（同骨干，逐项消融）

| 阶段 | 配置 | PCK@0.05 | med_px | mean_px |
|---|---|---|---|---|
| P1 | /4, 标准增广, hard 解码 | 0.984 | 2.92 | 4.86 |
| P2 | /2, hard 增广, weighted | 0.943 | 1.57 | 13.7 |
| **P3** | /2, hard 增广, **AA+robust** | **0.968** | **0.61** | **6.33** |
| P3+翻转 | + 180° 观察端歧义 | 0.950 | 0.64 | 14.5 |

### 分析与结论

1. **下限降到亚像素**：AA 渲染把 GT 下限 1.60→0.82px，传导到模型后 efficientvit_b1 median **0.61px**
   （hrnet 0.43px）。在 384 输入、6.1m 球场宽下，~0.6px ≈ **1cm 级**场地定位精度。

2. **重尾被压一半**：robust 解码（MAD 剔离群）在不损主体精度的前提下，把 mean 从 P2 的
   13.7→**6.33px**（repvit 25.7→13.3，convnext 17.7→11.9）。注意 P2→P3 增广相同，故 PCK@0.05
   0.943→0.968、median 1.57→0.61 **纯由 AA+robust 贡献**，是干净的解码/渲染收益。RANSAC 被实测否决。

3. **朝向可从内容学到（关键结论）**：加入 50% 180° 观察端歧义后，PCK@0.05 仅从 0.968 微降到 **0.950**，
   median 仍 0.64px、coverage 1.00——**没有塌到 ~50% 混淆**。说明具名通道 + 网络从透视前缩等内容线索
   **能自行判定近/远端**，绝大多数帧无需显式几何 tiebreak；只有少数真歧义帧进入尾部（mean 6.3→14.5），
   那才是非对称特征 tiebreak（发球线间距/记分牌/球员位置）该补的地方。这直接验证了 P0 的核心设计取舍：
   **把对称性交给"具名+内容"而非几何 RANSAC 身份搜索**是对的。

4. **骨干最终结论**：`efficientvit_b1` 在 hard+AA+robust 下 **PCK@0.05 0.968 / PCK@0.02 0.959 双料第一**，
   且 mean 尾部 6.33px 为全场最低（比 11.5M 的 hrnet 还稳），5.0M 参数最快。hrnet median 最低但 PCK 与
   尾部均不及，且 2.3× 参数+最慢；repvit 尾部仍最重。**确定 efficientvit_b1 为生产基线**。

### 下一步（P4）

- 接离线 2D→3D：用 efficientvit_b1 的 22 个交点 + `court_kp_official_world.json` 解 DLT 单应 + PnP 相机。
- 少数歧义帧补非对称 tiebreak（近/远发球线间距比 + 视频级时序一致性投票）。
- 落地新后端 `line_heatmap`（`perception/court/`），与 heatmap/line_fit 并入 `auto` 择优；
  渲染端 AA + /2 输出 + robust 解码作为默认。

## P4 系统接入（2026-06-14）：2D→3D + 朝向 tiebreak + 并入 auto

把 P3 胜出的 efficientvit_b1 落地为生产后端，目标是提升低角度/大变形/不完整球场的标定准确率。

### 1. 2D→3D（DLT + PnP）

`line_heatmap` 后端 `calibrate()`：12 具名线热图 → 逐线拟合求交还原 22 交点 → 与
`court_kp_official_world.json` 世界坐标配对 → `solve_homography`（**RANSAC DLT**，reproj 门控防幻影）
→ `estimate_camera`（**solvePnP** 外参，焦距取画面宽先验）。预设 `compute_camera: true`，相机参数
直接喂给 `monotrack` 重建器做 3D。实测真实帧 reproj **0.9–2.1px**，相机解算成功。

### 2. 不完整球场（核心优势，已验证）

具名线求交天然支持画面外角点：线由可见脊像素拟合，交点可外推到画面外。把帧顶部 35%（含远端底线）
裁掉后，仍能标定，reproj **1.2–4.3px**——这是相对点热图方案做不到的（点在画面外就丢）。

### 3. 朝向 tiebreak（透视前缩）

球场 180° 点对称，具名标签可能整体翻转。`_needs_flip` 用**透视前缩**判别：离相机更近的底线在
图像中更宽。取双打底线角点（远端 kpt 0&4 / 近端 17&21），若“远端”标签底线明显比“近端”宽
（比值 > `orientation_margin` 1.15）则判定标签翻转，按 `SYM_PERM=21-i` 整体重标。仅在四角全可见
且前缩差异明显时触发（近正交高角度视图不触发，因彼时歧义本身无关紧要）。

**验证**（valid 30 帧）：正确解码 **0/30 误触发**（不破坏正常帧，reproj 仍 0.9–2.1px）；
人为构造错标解码 **30/30 检出并恢复**到原始低 reproj 对应。

> 注：把图像旋转 180° 不是该场景——那会变成倒置的分布外图像，模型未训练过会整体失效。
> 真实“另一端机位”仍是正立画面（近端底线在下），模型原生可处理，标签一致。

### 4. 并入 auto

`auto` 候选从 (line_fit, heatmap) 扩为 **(line_fit, heatmap, line_heatmap)**，逐帧跑全部、按
`court_overlap_score`（BWF 线模型与白线重合度）择优。实测 5 帧 line_heatmap **全部胜出**
（overlap 0.55–0.999，对比 heatmap 0.42–0.77、line_fit 0.39–0.95）。

## 重要局限：泛化到业余低角度球场（2026-06-15 实测）

在 `assets/` 的 6 张真实业余低角度球场图（红/蓝/绿胶地、大斜角、部分出框）上用
`scripts/diagnose_court.py` 实测：**line_heatmap 与旧的 MobileNetV4 heatmap 后端均失败**。

| 图 | line_heatmap reproj/overlap | heatmap(mbv4) |
|---|---|---|
| image-17（干净蓝场） | 223px / 0.28 | 0 个置信点 |
| saac9zclk5n（正面绿场） | 4 点 / 0.01 | 0 个置信点 |
| tt（大斜角绿场） | 654px / 0.23 | 26px / 0.07 |
| 3rcxps5c599（红场） | 5652px / 0.31 | 0 个置信点 |

**根因**：两个学习型后端都只在 `data/court_kp_official`（广播比赛分布）上训练。P1-P3 的
"视角增广" 只在该分布内做透视扭曲，**无法合成业余球场的真实外观**（不同地色/光照/极端斜角/出框），
因此对这些分布外图像不泛化。这是**数据覆盖问题，不是架构或解码问题**——line_heatmap 反而比旧
heatmap 略好（至少出 22 点、overlap 0.18-0.31 vs mbv4 的 0）。

**已做的缓解**：
- `line_heatmap` 增加白线重合度门控 `min_overlap`（默认 0.30）+ reproj 门控，**分布外的幻觉球场被拒绝
  而非画出**（实测 6 张全部正确拒绝；广播验证集 12/12 仍通过，无误伤）。
- `scripts/diagnose_court.py`：画检测白线（青）+ 匹配球场（绿=采纳/红=拒绝）+ 关键点（黄），
  输出在 `assets/court_diag/`，可直观看到失败原因。

**真正的解法（待办）**：在代表性业余低角度球场数据上**微调 efficientvit_b1**（这些 assets 需标注，
或引入业余球场关键点数据集）。架构/解码（P1-P4）已就绪，缺的是 in-distribution 训练数据。
